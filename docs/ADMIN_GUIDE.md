# Руководство администратора

Панель управления: **https://admin.artifigence.ru**

Документ описывает повседневную работу с админ-панелью сервиса «Генератор постов».
Технические детали развёртывания см. в `DEPLOY_VPS.md` и `README.md`.

---

## 1. Вход в панель

### 1.1. Где взять токен

Доступ закрыт одним секретным токеном. Он хранится в файле `.env` на сервере и
генерируется один раз при первом развёртывании.

Получить токен (выполняется на вашем компьютере, не на сервере):

```powershell
# PowerShell в Windows
ssh root@5.101.4.137 "grep '^ADMIN_TOKEN=' /opt/genpost/.env | cut -d= -f2-"
```

```bash
# Linux / macOS / WSL
ssh root@5.101.4.137 "grep '^ADMIN_TOKEN=' /opt/genpost/.env | cut -d= -f2-"
```

Токен — строка из 44 символов. **Последний символ `=` является частью токена**:
если при копировании он потеряется, панель ответит «Invalid token».

Чтобы сразу положить токен в буфер обмена, добавьте `| Set-Clipboard` (PowerShell)
или `| xclip -selection clipboard` (Linux).

### 1.2. Ввод токена

1. Откройте https://admin.artifigence.ru
2. Вставьте токен в поле «Токен доступа»
3. Нажмите «Войти»

### 1.3. Сколько действует вход

Токен **постоянный** — он не меняется между сеансами. Но браузер хранит его
только до закрытия вкладки: при закрытии браузера или вкладки токен стирается и
его нужно ввести заново. Это сделано намеренно — в панели персональные данные
клиентов, и доступ не должен сохраняться на чужом компьютере.

Обновление страницы (F5) токен не сбрасывает.

Выйти принудительно — кнопка «Выйти» в правом верхнем углу.

### 1.4. Если панель показывает пустой экран

Пустой белый экран сразу после входа — признак ошибки в сборке фронтенда, а не
неверного токена. Проверить токен можно запросом:

```bash
ssh root@5.101.4.137 "T=\$(grep '^ADMIN_TOKEN=' /opt/genpost/.env | cut -d= -f2-); \
  curl -s -o /dev/null -w '%{http_code}\n' -H \"Authorization: Bearer \$T\" \
  https://admin.artifigence.ru/admin/params"
```

`200` — токен верный, проблема в интерфейсе (смотрите консоль браузера, F12).
`401` — токен неверный или скопирован не полностью.

## 2. Раздел «Параметры»

Раздел открывается сразу после входа. Здесь четыре настройки, которые применяются
**без пересборки контейнеров** — значения читаются из Redis при каждом обращении.

### 2.1. Что означают параметры

| Параметр | Смысл | Пример |
|---|---|---|
| **W** | Длительность доступа в **минутах** с момента оплаты | `5` — пять минут; `1440` — сутки |
| **Price** | Цена доступа в **рублях**, целое число | `250` |
| **Shop ID** | Идентификатор магазина ЮKassa | `1180416` |
| **Ykassa API** | Секретный ключ ЮKassa | `live_...` (48 символов) |

**Важно про W:** значение в минутах. `5` — это пять минут, а не пять часов.
Если нужен час — введите `60`, сутки — `1440`.

**Важно про Price:** цена фиксируется в записи клиента в момент оплаты. Изменение
цены **не влияет** на уже оплаченные сеансы — клиент дорабатывает на старых условиях.

### 2.2. Как изменить значение

1. Введите новое значение в поле
2. Нажмите **«Сохранить изменения»**
3. Дождитесь сообщения «Изменения сохранены»

Изменения вступают в силу немедленно: следующий клиент увидит новую цену на
странице оплаты.

Кнопка со стрелкой (⟳) рядом с заголовком **отменяет незаписанные правки** —
подставляет в форму значения, реально сохранённые на сервере.

### 2.3. Как поменять ключи ЮKassa

Поле **Ykassa API** всегда пустое — сервер отдаёт только маску ключа
(`****...Tm1Y`), настоящий ключ обратно не приходит.

Чтобы заменить ключ:

1. Введите новый **Shop ID**
2. Введите новый **Ykassa API** целиком
3. Нажмите «Сохранить изменения»

Если ключ менять не нужно — оставьте поле пустым, текущий ключ сохранится.

Ключи применяются без перезапуска: следующий платёж создаётся уже с новыми.

**Порядок при смене магазина:** сначала смените ключи в панели, затем проверьте
платёж на минимальную сумму. Старые платежи продолжат подтверждаться, потому что
статус всегда перезапрашивается из API ЮKassa.

### 2.4. История конфигураций

Правая колонка — до 50 снимков конфигурации. Каждый снимок хранит W, Price,
Shop ID и маску ключа на момент сохранения.

Клик по снимку **подставляет** его значения в форму, но **не применяет** их.
Чтобы применить — нажмите «Сохранить изменения».

Восстановить из снимка настоящий API-ключ нельзя: в истории только маска.
Если ключ был утерян, его нужно ввести заново из личного кабинета ЮKassa.

## 3. Раздел «Лиды»

Вкладка показывает всех, кто оставил email, — и оплативших, и нет.

### 3.1. Воронка

Семь плиток сверху:

| Плитка | Что считает |
|---|---|
| **Всего лидов** | Все записи в базе |
| **Новые** | Оставили email, но не оплатили |
| **Оплатили** | Все, кто когда-либо заплатил (включая истёкшие сеансы) |
| **Активны** | Оплатили, и сеанс ещё не истёк |
| **Истекло** | Оплатили, но время сеанса или стили закончились |
| **Выручка, ₽** | Сумма всех оплат за всё время |
| **Конверсия** | Доля оплативших от всех лидов, % |

«Оплатили» и «Активны» — **разные числа**, и это нормально. Клиент, у которого
сеанс истёк, остаётся в «Оплатили» и в выручке, но уходит из «Активны».

### 3.2. Фильтры

- **Статус** — все / новые / оплаченные / истёкшие
- **Дата с / Дата по** — по дате первого обращения (когда оставили email)
- **Поиск по email** — часть адреса, регистр не важен

Фильтры применяются сразу при изменении. Воронка при этом **не фильтруется** —
она всегда считается по всей таблице, чтобы не терять общую картину.

### 3.3. Таблица

Четыре колонки: email, статус, дата захвата, дата оплаты. По 50 записей на
страницу, внизу — переход между страницами.

Статусы:

- **Новый** (серый) — email оставлен, оплаты не было
- **Оплачен** (зелёный) — сеанс активен
- **Истёк** (жёлтый) — оплата была, доступ закончился

### 3.4. Экспорт CSV

Кнопка «Экспорт CSV» выгружает **все** записи текущего фильтра (не только видимую
страницу) — 14 полей, включая согласия, IP-адрес согласия, User-Agent и срок
удаления.

Файл в кодировке UTF-8 с BOM — Excel открывает кириллицу корректно, без
дополнительных настроек. Разделитель — точка с запятой не используется, поля
разделены запятыми.

### 3.5. Сроки хранения и автоудаление

| Категория | Срок | Основание |
|---|---|---|
| Оставил email, не оплатил | **30 дней** | Согласие не реализовано в договор |
| Оплатил | **365 дней** | Налоговые проверки, возвраты |

Удаление автоматическое: просроченные записи вычищаются при открытии списка лидов
и при старте приложения. Отдельной кнопки «удалить» нет — это требование ФЗ-152:
данные не должны храниться дольше необходимого.

Колонка «Удалить после» в CSV показывает точную дату для каждой записи.

### 3.6. Что делать с выгрузкой

CSV содержит персональные данные. При передаче файла:

- не отправляйте его в мессенджеры и на личную почту без шифрования;
- храните не дольше, чем нужно для задачи;
- удаляйте после использования.

## 4. Типовые операции

### 4.1. Изменить цену

Параметры → Price → новое значение → «Сохранить изменения».
Проверить: https://artifigence.ru/payment/price должен отдать новую цену.

### 4.2. Увеличить длительность сеанса

Параметры → W → значение в минутах → «Сохранить изменения».
Уже оплаченные сеансы не изменятся — у них W записан в базе.

### 4.3. Проверить конкретный платёж

1. Лиды → поиск по email
2. Посмотреть статус и дату оплаты

Если клиент утверждает, что заплатил, а статус «Новый» — откройте платёж в
личном кабинете ЮKassa по ID (колонка «ID платежа» в CSV) и проверьте статус там.
Webhook мог не дойти при сетевом сбое; в этом случае помогает повторный заход
клиента на сайт — фронт сам перезапрашивает статус.

### 4.4. Выгрузить лидов за период

Лиды → Дата с / Дата по → «Экспорт CSV».

### 4.5. Сменить токен админки

Токен хранится в `.env` на сервере. Замена:

```bash
ssh root@5.101.4.137
cd /opt/genpost
NEW=$(openssl rand -base64 32)
sed -i "s|^ADMIN_TOKEN=.*|ADMIN_TOKEN=${NEW}|" .env
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --force-recreate backend
echo "$NEW"   # сохраните в менеджер паролей
```

После пересоздания backend старый токен перестаёт действовать.

## 5. Безопасность

- **Токен = полный доступ к персональным данным.** Не пересылайте его в чатах и
  не храните в заметках. Менеджер паролей — минимально приемлемое место.
- **Не входите в панель на чужих компьютерах.** Даже при закрытии вкладки токен
  остаётся в истории браузера до её очистки.
- **Не публикуйте адрес панели.** Поддомен `admin.` закрыт от индексации
  (`X-Robots-Tag: noindex`), но это не защита от того, кто знает адрес.
- **Не отключайте HTTPS.** Токен передаётся в заголовке `Authorization`; без TLS
  он виден любому в сети.
- **Проверяйте сроки хранения.** Записи удаляются автоматически, но выгрузки CSV
  живут отдельно от базы и требуют ручного контроля.

## 6. Если что-то не работает

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| «Invalid token» | Токен скопирован не полностью | Проверить длину: ровно 44 символа, последний — `=` |
| «Invalid Authorization scheme» | Токен не вставлен, отправлен пустой заголовок | Ввести токен заново |
| 503 при входе | На сервере не задан `ADMIN_TOKEN` | Проверить `.env` на сервере |
| Пустой экран после входа | Ошибка сборки фронтенда | Открыть консоль браузера (F12), посмотреть ошибку |
| Вход сбрасывается при каждом обновлении | Токен не сохраняется | Проверить, что браузер не блокирует `sessionStorage` |
| Не сохраняются параметры | Значение не целое или ≤ 0 | W и Price — целые положительные числа |
| Платёж не создаётся | Пустые ключи ЮKassa | Параметры → заполнить Shop ID и Ykassa API |
| Webhook не приходит | Уведомления не включены в ЛК ЮKassa | Интеграции → HTTP-уведомления → `https://artifigence.ru/payment/webhook`, событие `payment.succeeded` |

Диагностика на сервере:

```bash
ssh root@5.101.4.137
cd /opt/genpost

# состояние контейнеров
docker compose -f docker-compose.yml -f docker-compose.prod.yml ps

# последние ошибки бэкенда
docker logs public-backend --tail=50

# пришли ли уведомления от ЮKassa
docker logs public-backend 2>&1 | grep 'POST /payment/webhook'

# журнал последнего деплоя
tail -20 /opt/genpost/deploy.log
```
